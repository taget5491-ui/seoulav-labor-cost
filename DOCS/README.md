# 공사일보 기반 투입계획 자동 입력 개발 명세

## 목적

`DOCS/공사일보_DSR-B타워-1층-강당-및-컨퍼런스-A홀-AV시스템-구축_260805.pdf`를 기준 양식으로 삼아, 사용자가 공사일보 PDF를 첨부하면 현재 웹 프로그램의 `투입 계획` 행을 자동 생성하는 기능을 구현한다.

이 문서는 다음 Codex 작업자가 기존 맥락을 다시 조사하지 않고 바로 개발을 이어갈 수 있도록 작성한 인수인계 명세다.

## 기준 문서 분석 결과

기준 PDF는 Excel에서 출력한 A4 1페이지 공사일보다. 텍스트 레이어가 있어 우선 `pdfjs-dist` 기반 텍스트 추출을 사용하고, 텍스트가 없는 스캔 문서는 후속 OCR 대상으로 둔다.

확인된 값:

| 문서 항목 | 예시 값 | 프로그램 대상 |
|---|---|---|
| 공사명 | DSR B타워 1층 강당 및 컨퍼런스 A홀 AV시스템 구축 | 공사 정보 `공사명` |
| 주요 작업 내용 | 장비 철거 | 투입 계획 `작업내용` 기본값 |
| 업체명 | (주)서울영상테크 | 참고값. 자사명은 외부업체로 만들지 않음 |
| 공사기간 | 2026-08-05 ~ 2026-10-31 | 공사 정보 `시작일`, `종료일` |
| 작성일자 | 2026년 8월 5일 수요일 | 투입 계획 `투입일자` |
| 금일 작업 현황 | 장비철거 및 세부 작업 목록 | 투입 계획 `작업내용` 상세값 |
| 주간 업체/인원 | 서울영상테크 3명, RTA 3명 | 업체별 투입 계획 행 |
| 야간 업체/인원 | 없음 | 값이 있을 때 야간 행 생성 |
| 다음 작업 현황 | 천장 배관 포설 | 미리보기 참고값. 기본 자동 저장 대상 아님 |

문서의 `다음 작업 현황`에도 업체명과 인원이 표시되지만 날짜가 명확하지 않다. 잘못된 투입일을 만들지 않도록 Phase 1에서는 `금일 작업 현황`만 자동 입력하고 다음 작업은 미리보기에서만 보여준다.

## 자동 매핑 규칙

### 공사 정보

- 공사명은 문서의 `공 사 명` 값을 사용한다.
- 사업장은 공사명과 사내 사업장 목록을 대조해 추론한다. 이 기준 문서는 `DSR`로 매핑한다.
- 공사기간의 앞 날짜는 `startDate`, 뒤 날짜는 `endDate`로 매핑한다.
- 공사명과 사업장이 현재 열려 있는 공사 건과 다르면 사용자에게 덮어쓰기 여부를 확인한다.

### 투입 계획 행

- 작성일자를 모든 금일 투입 행의 `workDate`로 사용한다.
- 작업내용은 `금일 작업 현황` 전체를 줄바꿈을 보존한 문자열로 사용한다. 내용 추출이 실패하면 `주요 작업 내용`을 대체값으로 사용한다.
- 주간 인원은 `dayType: "weekday"`를 기본으로 하되, 기존 `dayTypeFromDate(workDate)` 규칙을 적용해 토요일/휴일을 계산한다.
- 야간 인원은 현재 모델에 야간 구분이 없으므로 바로 저장하지 말고 미리보기에서 경고한다. 야간 자동 입력을 구현하려면 `LaborRow`와 DB에 시간대 또는 야간 여부 필드를 먼저 추가한다.
- 인원 0 또는 빈 셀은 행을 만들지 않는다.
- 같은 업체가 주간과 야간에 모두 존재해도 각각 별도 후보로 유지한다.

### 업체명 정규화

현재 투입구분 목록은 `자체`, `RTA`, `VSEnt`, `코어워커`, `직접입력`이다.

| 추출 업체명 | 투입구분 | 업체명 처리 |
|---|---|---|
| 서울영상테크, (주)서울영상테크, ㈜서울영상테크 | 자체 | 외부업체명 없음, 업체 견적금액 0원 |
| RTA | RTA | 고정 업체명 `RTA` |
| VSEnt 및 띄어쓰기/대소문자 변형 | VSEnt | 고정 업체명 `VSEnt` |
| 코어워커 | 코어워커 | 고정 업체명 `코어워커` |
| 그 외 업체 | 직접입력 | 추출된 업체명을 그대로 입력 |

기준 문서의 `서울영상테크 3명`은 `자체` 행으로, `RTA 3명`은 `RTA` 행으로 생성한다. PDF에는 업체 견적금액이 없으므로 모든 자동 생성 행의 `contractorQuoteAmount`는 0원으로 두고 사용자가 확인·입력하게 한다.

## 권장 사용자 흐름

1. `투입 계획` 카드 상단에 `공사일보 PDF 불러오기` 버튼을 추가한다.
2. PDF 선택 즉시 브라우저에서 분석하고 서버에는 아직 저장하지 않는다.
3. 추출 결과 미리보기에서 공사 정보와 생성될 행을 표로 보여준다.
4. 각 행에 `추가`, `제외`, `기존 행과 병합` 선택을 제공한다.
5. 사용자가 `투입 계획에 적용`을 눌렀을 때만 현재 폼 상태를 변경한다.
6. 기존 행은 자동 삭제하지 않는다. 동일 날짜·업체·작업내용이 있으면 중복 경고를 표시한다.
7. 최종 DB 저장은 기존 `견적 저장` 동작을 그대로 사용한다.

## 구현 권장 구조

- `lib/daily-report.ts`
  - PDF 텍스트를 순수 함수로 파싱한다.
  - `parseDailyReport(textItems)`와 정규화 함수를 둔다.
- `types/daily-report.ts`
  - 추출 결과, 경고, 업체별 인력 후보 타입을 정의한다.
- `components/daily-report-import-dialog.tsx`
  - 파일 선택, 분석 상태, 미리보기, 적용을 담당한다.
- `app/labor-cost-app.tsx`
  - 다이얼로그를 열고 승인된 결과만 현재 공사 정보와 `rows`에 병합한다.
- `lib/pdf-labor.ts`
  - 견적서 노무비 전용이므로 직접 수정하지 말고, 공통 PDF 로더가 필요하면 별도 유틸로 분리한다.

Phase 1은 클라이언트 분석으로 구현한다. 원본 공사일보 영구 보관이 필요해지는 시점에 R2 업로드 API와 D1 메타데이터를 별도 추가한다.

## 파싱 시 주의점

- PDF 텍스트 추출 결과는 표의 시각적 열 순서와 문자열 순서가 다를 수 있다. 텍스트 위치 좌표(`transform`)를 함께 사용해 행과 좌/우 영역을 구분한다.
- 법인 표기 `(주)`, `㈜`, 공백, 영문 대소문자는 정규화한 후 업체를 매칭한다.
- 날짜는 한국어 형식과 `YYYY-MM-DD` 형식을 모두 지원한다.
- 인력현황 표의 `소계`는 검증값으로만 사용하고 업체별 인원으로 다시 행을 만들지 않는다.
- 사진 캡션의 업체명이나 숫자를 인력으로 오인하지 않도록 인력현황 표 영역 안의 텍스트만 사용한다.
- 추출 신뢰도가 낮거나 업체명·인원의 개수가 맞지 않으면 자동 적용을 막고 수동 확인을 요구한다.

## 완료 조건

- 기준 PDF에서 공사명, DSR, 공사기간, 작성일자, 금일 작업 내용이 정확히 추출된다.
- 자체 3명과 RTA 3명이 별도 후보 행으로 표시된다.
- 자체 행은 외부업체 비용이 0원이고, RTA 행의 업체 견적금액은 사용자 입력 전 0원이다.
- 기존 투입 계획 행을 지우지 않고 선택한 후보만 병합한다.
- 동일 문서를 두 번 적용하면 중복 경고가 표시된다.
- 잘못 추출한 값은 미리보기에서 수정할 수 있다.
- 파서 단위 테스트에 기준 문서와 유사한 텍스트 배열, 업체명 변형, 빈 야간 행, 다중 업체 사례가 포함된다.
- `npm run build`가 성공한다.
